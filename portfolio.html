1. Organisation Overview: Django Girls Sierra Leone

Organisation Name & Brand Logo

Official Name: Django Girls Sierra Leone

Headquarters: Freetown Innovation Hub & Limkokwing ICT Labs, Freetown, Sierra Leone

Continuation of Assignment 1: Directly expands the Assignment 1 Authentication Portal (auth_project) into a full-scale web-based community and organisation management platform.

Background, Mission & Vision

Background: Founded as part of the global non-profit Django Girls initiative, Django Girls Sierra Leone empowers women across Freetown and regional universities to enter the software industry through free, practical coding workshops and peer mentorship.

Mission: To demystify software engineering by providing Sierra Leonean women with accessible learning materials, hands-on Python/Django and Web Programming bootcamps, and a supportive mentorship network.

Vision: A thriving, inclusive technology ecosystem in Sierra Leone where women lead as full-stack developers, innovators, and technical mentors.

Core Services & Target Users

Core Services Provided:

  • Hands-on Coding Workshops: Free in-person Freetown lab bootcamps and online training sessions.
  • Curated Learning Library: Self-paced tutorials in Python, Django, HTML/CSS, JavaScript, Data Science, and UI/UX Design.
  • 1-on-1 Developer Mentorship: Matching beginner coders with experienced Sierra Leonean software engineers.
  • Community Forum: Peer Q&A discussion board.

Target Users: Female university students, aspiring beginners in web programming, volunteer tech mentors, and community administrators.

Page / Section 2 — Problem Statement & User Research

2. Problem Analysis, User Needs & Proposed Solution

1. Existing Problem

Prior to this platform, community operations relied on disconnected tools—paper sign-up sheets at workshops, scattered WhatsApp links for tutorials, and manual spreadsheets for tracking attendance.

In Assignment 1, members could register and log in, but lacked interactive tools to register for events, track tutorial progress, upload profile pictures, or request mentors.

2. User Needs Identified

  • Members: Need a personalized dashboard that recommends workshops and tutorials matching their chosen coding interests and tracks completion percentage.
  • Mentees & Mentors: Need a structured directory to view developer profiles and send/accept mentorship requests.
  • Administrators: Need real-time engagement analytics, attendance tracking, and CSV reporting.

3. Proposed Solution

A centralized, database-driven PHP & SQLite (PDO) Web Community Management Platform featuring:

  • Secure authentication & role-based access control (Member, Mentor, Admin).
  • Interactive Dashboard with interest-based matching and progress bars.
  • Event capacity & attendance tracker, Learning Library, Discussion Forum, Mentorship Hub, and Admin Analytics Panel.

4. Target Audience

  • Primary Audience: Young women (ages 16–30) in Sierra Leone studying ICT or transitioning into web development.
  • Secondary Audience: Industry software engineers and university lecturers volunteering as technical mentors.
  • Organisational Admins: Chapter leads managing events, resources, and impact reports.

Page / Section 4 — Interface Design Specifications

Implemented User & Administrative Interfaces (1–9)

1. Homepage (index.php)
Learn to code. Build your future.
Split hero banner with Freetown coding photo, live database counter strip, 4 feature cards, and upcoming workshops preview.

UX Highlights: Clear call-to-action buttons (Create Free Account / Open Dashboard) and live community statistics pulled dynamically from SQLite.

2. Registration (signup.php)
Fields: Full Name, Email, Password + Confirm, 6 Interest Pill Checkboxes, Experience Level, Bio & Mentor Opt-in.

UX Highlights: Validates email uniqueness and password complexity (8+ chars, letter + number), hashes with password_hash(), and stores member interests for dashboard personalization.

3. Login Page (login.php)
Authentication: Email + Password with Show/Hide toggle, CSRF token verification, and 1-click Demo Quick-Fill buttons.

UX Highlights: Prevents session fixation via session_regenerate_id(true), checks active account status, and records last_login timestamp.

4. Member Dashboard (dashboard.php)
Personalized Hub: Greeting Banner + KPI Strip + Training Progress Bar + Next Steps Checklist + Account Activity + Matched Workshops.

UX Highlights: Prioritizes workshops and tutorials that match the member's selected topics with a pink ★ Matches your interest badge.

5. Profile & Directory (profile.php / members.php)
Features: Custom Avatar Upload (JPG/PNG/WebP up to 2MB) with live preview, 4 preset SVG avatars, bio, interests, and public profile showcase.

UX Highlights: Validates real MIME types via finfo and getimagesize(), plus a searchable Member & Team Directory.

6. Events & Workshops (events.php)
Features: Filter by Workshop / Training Session / Event, live seat capacity bar (X of Y seats left), 1-click Register/Cancel, and History table.

UX Highlights: Prevents overbooking when capacity is reached and tracks Registered vs Attended status.

7. Learning Resources (resources.php)
Features: Category filter chips (Python, Django, HTML & CSS, JS, Data Science, UI/UX), search box, and ✓ Mark Complete toggle.

UX Highlights: Dynamically recalculates the member's overall training completion bar as tutorials are marked done.

8. Community & Mentors (community.php / mentors.php)
Features: Discussion board with threaded replies (topic.php) + Mentorship Hub where members send requests and mentors Accept/Decline.

UX Highlights: Fosters peer collaboration and direct mentor-mentee connections with status badges.

9. Admin Panel (admin/index.php, users, events, resources)
Features: 8 KPI metrics, monthly signup & interest charts, CSV exports, user role/status controls, event creation & attendance marking.

UX Highlights: Protected by require_admin(); includes formula-injection-safe CSV downloads and print view.

SECTION 5 — SYSTEM ARCHITECTURE, DATABASE ERD & WORKFLOWS

3-Tier PHP Application Architecture, 7-Table Relational Database Schema (ERD), Sitemap & User Workflows

Page 4 of 5 • Section 5 (System)
1. System Architecture

3-Tier Web Application Architecture

Client Browser (HTML5 / CSS3 / JS) ↔ Apache + PHP 8 Logic & Security (CSRF / Auth / PDO) ↔ SQLite Relational DB (djangogirls.sqlite)

Security & Shared Modules: Central configuration in config.php manages sessions, PDO connection with PRAGMA foreign_keys = ON, CSRF token verification, and role guards (require_login(), require_admin()). Shared UI templates live in includes/header.php and includes/footer.php.

3. Navigation Structure

Platform Sitemap & Role Access Hierarchy

  • Public / Guest Tier: index.php (Landing Page) → signup.php (Registration) ↔ login.php (Authentication).
  • Authenticated Member Tier: dashboard.php (Hub) → events.php | resources.php | community.php & topic.php | mentors.php | members.php & member.php | profile.php | logout.php.
  • Administrator Tier (/admin/): admin/index.php (Analytics & CSV Export) → admin/users.php | admin/events.php | admin/resources.php.
2. Database Design & Entity-Relationship Diagram (ERD)

Relational Database Schema (7 Normalized Tables with Foreign Keys)

1. users
  • PK id (INTEGER)
  • full_name (TEXT)
  • email (TEXT UNIQUE)
  • password_hash (TEXT)
  • role ('member'|'admin')
  • interests (TEXT CSV)
  • experience_level (TEXT)
  • bio, avatar (TEXT)
  • is_mentor, active (INT)
  • created_at, last_login
2. events & 3. registrations
  • PK events.id
  • title, description, type
  • topic, event_date, location
  • capacity (INTEGER)
  • event_registrations:
  • PK id
  • FK event_id → events.id
  • FK user_id → users.id
  • status ('registered'|'attended')
4. resources & 5. progress
  • PK resources.id
  • title, description
  • category, level, url
  • resource_progress:
  • PK, FK user_id → users.id
  • PK, FK resource_id → resources.id
  • completed_at (TEXT)
6. topics, 7. replies & 8. mentorships
  • topics: PK id, FK user_id, title, body
  • replies: PK id, FK topic_id, FK user_id, body
  • mentorships:
  • PK id
  • FK mentee_id → users.id
  • FK mentor_id → users.id
  • message, status ('pending'|'accepted')
4. Main System Workflows

Core End-to-End Operational Workflows

Workflow A: Member Onboarding & Personalized Learning

Sign Up & Pick Interests → Log In (Session + CSRF) → Dashboard Ranks Matched Content → Join Workshop & Mark Tutorials Done

Workflow B: Mentorship & Administrative Reporting

Mentee Sends Request → Mentor Accepts on Dashboard → Admin Marks Event Attendance → Admin Exports CSV Analytics
